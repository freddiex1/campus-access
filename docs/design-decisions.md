what does A Request look like :   One request is a Python dictionary with five fields: id (like A001, made by the system), fellow_id (the person’s number, like F001), card_type (visitor, student or staff), status (starts as requested) and approved_by (empty, None, until a staff member approves). If the input is invalid, create_request raises a ValueError with a clear message and stores nothing, so the program doesn’t crash and no bad data gets in.
what does create_request return:    One request is a dictionary with five fields. id (like A001) is the request’s own number, made by the system. fellow_id (like F001) is the number of the person asking, which the user types in. card_type is visitor, student or staff. status starts as requested, and approved_by is empty (None) until staff approve it. If the input is invalid, create_request raises a ValueError and stores nothing.
How do functions report invalid input? :    They raise a ValueError with a clear message. The check runs before anything is stored, so nothing changes. The menu catches the error and prints it instead of crashing. 
Where is the next ID generated, and why does it survive a restart?:        Where is the next ID generated, and why does it survive a restart?
In _next_id() in storage.py. It finds the highest number among the existing requests and adds 1. After a restart, load_requests brings the old requests back, so the highest number is still known and the next ID continues (A001 exists, so the next is A002). 
How does workflow.py change records? :     Only through storage.update_request. Each function (approve, issue, return) first gets the record and checks its status. Only if the checks pass does it call update_request, which swaps in the new status and approver.
What happens if the saved JSON file is invalid? : load_requests raises a ValueError with a clear message and leaves the data already in memory untouched. It builds the new data on the side and replaces the old data only if every record passes. main.py stops with a message instead of starting empty.
What data must never change when an action is rejected? :All five fields of the record (id, fellow_id, card_type, status, approved_by) and the ID counter (the next ID). A rejected action must leave everything exactly as it was.
